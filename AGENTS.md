# Markdown BBCode

## Scope

Windows Markdown editor built with Tauri 2, Rust, vanilla JavaScript, Tiptap 3 and CodeMirror 6. Read DESIGN.md before changing behaviour. Ordinary .md is the default. Nexus and Steam guide BBCode are optional on-demand outputs (Steam modeled on the sibling project `..\Steam Markdown`). Supports both Portable mode (beside executable via `Portable.txt` or `portable-data`) and Installed NSIS mode (`AppData`).

## Development

Run `npm ci`, then `npm run tauri dev`. `npm run portable` compiles the binary and deploys directly to `D:\Apps\Markdown BBCode\Markdown BBCode.exe`, gracefully closing (`--graceful-close` single-instance IPC plus `WM_CLOSE` fallback) and relaunching any running instance in that folder while preserving `portable-data`. `npm run build:installer` builds a per-user signed NSIS installer. Keep dependencies locked. WebView2 is required. This project lives in its own standalone Git repository (`Fuzen777/Markdown-BBCode`); never commit builds, dependencies, signing private keys or recovery data. GitHub Releases run only on explicit `workflow_dispatch` or `release/v*` tags.

## Persistence

src/documents.js saves authoritative Markdown only. Never create, check or delete automatic BBCode companions. Export is explicit and uses revision-checked replacement confirmation. Protect open source paths and original import paths. Preserve unknown YAML, invalid source and untouched raw text. Settings and recovery stay in `portable-data` beside the executable when running portable, or under `%APPDATA%\Markdown BBCode` when installed (migrating existing `%APPDATA%\BBCode Editor` data only on first launch if needed); legacy session migration retains pending imports and backs up version-1 sessions. Window bounds persist in `window-state.json` via `tauri-plugin-window-state` with startup off-screen/taskbar rescue (`resolveRescuedWindowRect`). Non-blocking update checks (`check_for_update`), pre-update conflict/flush guards (`install_update`), and portable SHA-256 + Ed25519 minisign zip verification protect upgrades across both distribution modes.

## Editing And Conversion

src/markdown.js owns schema, Markdown conversion, block segmentation and Nexus output (retaining `\n\n` blank lines between regular paragraphs and between titles/headings and paragraphs, gluing `[list]`/`[list=1]` openings and their first `[*]` item directly to preceding blocks with `\n` after `[/list]`, and using `\n` before and after `[hr]`, `[quote]`/callout and `[code]` blocks); src/steam-bbcode.js owns Steam guide BBCode conversion; src/callout.js owns Obsidian callouts. src/bbcode-import.js owns one-time imports across Nexus and Steam tags. src/document-format.js owns frontmatter and target-aware export (`defaultTarget` overridable globally via `DocumentStore.bbcodeTarget` or explicitly via legacy `.mdbbcode` YAML). Use documentToBBCodeWithWarnings for complete document export, not the body-only converter.

src/visual-editor.js coordinates Visual, Hybrid and Source. src/block-controls.js owns Visual block menus and dragging. src/hybrid-editor.js replaces only the active enclosing block span and preserves untouched source; src/source-formatting.js shares source formatting operations. Markdown may merge adjacent compatible lists. Visual serialization can normalize an edited document. Editors are recreated on mode/tab changes, resetting undo.

The Tiptap Markdown manager uses an isolated Marked instance and validated schema JSON. Its escapeMarkdownSyntax override escapes literal pipes to distinguish spoiler delimiters. Recheck this override when upgrading the beta Markdown API. Unsupported HTML must stay raw and never execute in previews.

## Metadata And Preferences

Ordinary Markdown accepts arbitrary optional YAML; only legacy metadata and the `bbcodeLint` key (per-file BBCode warning override, read/written by `readBBCodeLintProperty`/`withBBCodeLintProperty` in src/document-format.js, touching only its own line) are app-reserved. Save As does not inject metadata. Conversion validation happens at export, never as a prerequisite to saving. YAML Document API retains unknown fields/comments. src/properties/ owns the Properties panel (properties-model.js: YAML Document model, type inference and conversion, byte-identical until edited; properties-panel.js: UI). It is a lazy chunk imported by `MarkdownEditor.showProperties` only when a document has front matter or properties are added; keep it out of the main bundle. Front matter edits in Visual/Hybrid (the panel and the `bbcodeLint` switch) go through `MarkdownEditor.replacePrefix`, which refuses a prefix that would change how the body parses. Hybrid blocks render into `#hybrid-blocks` inside the `#hybrid-editor` scroller (the panel sits above them); `HybridEditor` uses `callbacks.scroller` for scrolling and gutter hit-testing. Selection indicators derive from Tiptap transactions and selections.

src/colors.js owns conversion/validation; src/color-picker.js owns the picker. Session preferences.lastColor and preferences.colorMode are global portable settings. Selection never overwrites lastColor. Save input-mode changes immediately, including cancellation. Preserve editor bookmarks across the picker in every mode.

## Linting

src/lint owns opt-in markdownlint support. markdownlint is only imported by src/lint/lint-worker.js, which runs in a lazily created Web Worker; keep it out of the main bundle so startup and shutdown cost nothing when linting is off. src/lint/lint-controller.js owns debounce/latest-wins scheduling, src/lint/lint-config.js the app rule profile, presets, `lint` settings normalization and preset/override merging, src/lint/lint-project-config.js the read-only `.markdownlint.jsonc`/`.markdownlint.json` discovery (JSONC, relative `extends`, per-folder cache cleared on window focus), and src/lint/lint-panel.js the `Outline | Lint` tabs and problem list. src/settings/settings-dialog.js (Settings dialog, `Ctrl+,`) and src/settings/lint-rule-catalog.js (rule browser model generated from markdownlint's config schema, aliased in vite.config.js as `markdownlint-config-schema` because the package does not export it) are dynamically imported on first open; lint-project-config.js only once linting is enabled. `.mdbbcode` format rules (MD033 off, wrapper-aware MD041 as `MBB-MD041` reported as MD041) live in src/lint/mdbbcode-rules.js and apply on top of app and project configs via `withFileTypeOverrides`; the editor's HTML wrappers are listed once in src/editor-wrappers.js. Keep all three out of the main bundle and check `npm run build` chunk sizes after changes. src/lint/lint-markers.js (Hybrid gutter marks via shell classes and active-block CodeMirror underlines with a hover tooltip, Visual ProseMirror node decorations, floating-rail ticks) is also a lazy chunk, loaded once a lint result is ready with markers on; its pure mapping lives in src/lint/lint-marker-model.js. Markers never edit the document or add height; HybridEditor only calls `callbacks.onRendered` after render/mount/restore. Quick fixes use the worker's per-problem `fix` edit (`fixEditFor` in lint-engine.js, matching markdownlint's applyFix) and `fixAll` (markdownlint `applyFixes` in the worker); Source applies them with `execCommand('insertText')` so Ctrl+Z works, Hybrid through `replaceBodyRange`, Visual by reloading after a confirmation. `MarkdownEditor.readOnly` must call `setEditable(…, false)`: Tiptap's default emits a fake `update` that re-serializes Visual documents whenever a dialog opens. vite.config.js pre-bundles `markdownlint` and `@tiptap/pm/*` so the dev server does not reload mid-test on first lint. BBCode export warnings run in a second lazy worker (src/lint/bbcode-worker.js with src/lint/bbcode-lint.js) driven by its own LintController, because converting takes about 0.6 s at 50 KB and 2.4 s at 100 KB; they stop above 100 KB (`BBCODE_WARNINGS_MAX_KB`). bbcode-lint.js only reads existing converter output: it converts the whole document and, when anything is reported, each top-level block alone to attribute warnings to lines; never change export behaviour for it. The Lint tab's Folder scope is src/lint/lint-folder-audit.js (lazy UI) and src/lint/folder-audit-model.js (pure walk/read/lint with `signal.cancelled`, 500 files, 2 MB per file), linting through `LintController.lintOnce` and the same project-config resolution (`projectConfigFor` in main.js); it runs only when the scope opens or on Lint Again, and must never add Folder Browser badges or background scans.

## Validation And Documentation

Run npm test, npm run test:ui, npm run lint, npm run build, Rust tests, formatting checks and Clippy. After packaging, npm run test:native (scripts/native-smoke.mjs) exercises the actual desktop bridge in an isolated folder; close other app instances first. Test runners enforce hard process-tree timeout limits via scripts/run-with-timeout.mjs (30s unit tests, 180s Playwright UI (175s Playwright globalTimeout; the suite passed 100 tests and outgrew 120s) with a 20s webServer startup limit and maxFailures: 5, and 60s native smoke, terminating hung process trees with exit code 124). Because Playwright and native smoke rely on local loopback connections and Edge or WebView2, run npm run test:ui and npm run test:native outside restrictive network/process sandboxes. Keep DESIGN.md, FEATURES.md, README.md, CHANGELOG.md and VALIDATION.md aligned. Development file watching excludes runtime caches and builds.

## Hybrid Rows And Icons

segmentMarkdown preserves exact spans and emits individual top-level space blocks. Hybrid hides each block's final line terminator in CodeMirror and restores it on edits; do not append separator rows inside content blocks. Blank-line actions operate on real source spans. Controls belong in an absolute gutter. Visual and Hybrid block controls center on their block's first line through `firstLineCenter` (src/first-line.js); Hybrid realigns on hover and focus. src/icons.js centralizes local Material Symbols Rounded SVG rendering and accessible hover/focus tooltips. An element with a custom tooltip keeps its text in `data-tooltip`, never `title` (which would show a second, native tooltip): `setButtonIcon` writes only `data-tooltip`, and a `title`-only MutationObserver moves any later `title` on a `[data-tooltip]` element into it, so code may keep setting `.title`.
