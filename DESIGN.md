# Markdown BBCode Design

## App Declarations

| Declaration | Choice |
| --- | --- |
| Signature color | Warm Amber (`#b45309` fill, `#ffffff` on-fill, `#f4b570` dark text, `#9a3412` light text) |
| Density | Compact |
| Icon set | Material Symbols Rounded |
| Touch support | No |
| Themes | Dark and Light (`prefers-color-scheme`) |
| Deviations | Retains OS-matched Light Mode with matching zero-chroma neutral roles; adds blue info callouts (`#60a5fa`) and subtle amber spoiler tints for document semantics |

## Color System

Dark Mode maps directly onto the workspace shared [DESIGN](../../DESIGN.md) zero-chroma neutral ladder (`--page: #111111`, `--surface: #171717`, `--control: #262626`, `--active-fill` / `--border: #404040`, `--accent` / `--text-secondary: #a1a1a1`, `--text: #f5f5f5`, `--muted: #737373`) alongside shared status tones (`#ff6467` error, `#ffb900` warning, `#05df72` success), Surface+Border tooltips, `60%` black modal backdrops, tabular counters, and `4 px` neutral scrollbars. Hover and toggled/active controls stay strictly neutral (`--control` / `--active-fill`); Warm Amber appears sparingly only on primary actions (`.primary`, `.update-pill`), `:focus-visible` rings, the `[M↓]` monogram, prose links, active folder open-file dots, update badges, and task checkbox accents.

## Purpose

A fast Windows Markdown editor with optional Nexus Mods and Steam guide BBCode export, built with Tauri 2 and Tiptap 3 in both Portable (`portable-data` beside `Markdown BBCode.exe`) and Installed (`%APPDATA%\Markdown BBCode`) modes. Ordinary .md files are the default; .markdown and existing .mdbbcode documents remain supported.

## Documents And Saving

Autosave only the editable source after 750 ms and recovery after 250 ms. Opening, editing, saving and closing must never create, update, check or delete a BBCode companion. Existing companions remain untouched. Preserve source revision checks, atomic writes, recoverable drafts, tabs and single-instance opening. When the open file changes on disk externally (on focus, polling, save conflict, or session recovery), perform a line-level 3-way merge (`mergeThreeWay` in `src/diff.js`): auto-reload clean documents and auto-sync non-intersecting line additions/removals while exposing a non-blocking `View Diff` / `Revert Sync` review banner, and raise an interactive Unified / Side-by-Side Diff View (`#diff-dialog` in `src/diff-dialog.js`) with collapsible context and per-hunk `Keep Mine` / `Use Disk` / `Keep Both` resolution whenever changes intersect. When an open file is deleted or moved externally on disk, expose `Review Missing File` and `Close Tab` actions in the notice bar, allow closing clean missing tabs and quitting the app directly without recreating deleted files or blocking shutdown, and prompt via the `File Missing On Disk` dialog (`Keep My Edits`, `Save As`, `Close Tab` / `Close Without Saving`, `Cancel`) before discarding unsaved edits.

New documents and one-time imports default to .md without mandatory metadata. Preserve ordinary YAML frontmatter without interpreting unrelated format/version/target keys as application settings. Existing explicit mdbbcode metadata remains readable; validate export target only on export. Unsupported source stays source-editable and saved.

## BBCode Export

Copy BBCode converts the current document on demand using the header `Nexus | Steam` dialect switcher (persisted globally as `bbcodeTarget` in `session.json`, or overridden by explicit legacy `.mdbbcode` `target:` YAML). Export BBCode chooses a `.bbcode` or `.txt` destination and writes once, with explicit revision-checked replacement for an existing file. Never replace the editable source or an original BBCode import. In Nexus mode, keep standard blank lines (`\n\n`) between regular paragraphs and between titles/headings and paragraphs, glue `[list]` / `[list=1]` openings and their first `[*]` item directly onto preceding headings, paragraphs, `[hr]`, `[quote]` or `[code]` blocks (`...[list][*]...`) while keeping `\n` after `[/list]` and `\n` before and after `[hr]`, `[quote]` (including callouts) and `[code]` blocks across top-level and nested contexts, preserving any extra intentional blank lines and keeping scroll-sync offsets aligned; callouts become titled quotes/spoilers, tasks become checklist text, and tables become readable text. In Steam mode (modeled on `Steam Markdown`), emit Steam guide BBCode (`[h1]`–`[h3]` with no trailing blank line and `h4`–`h6` downgrade warnings, `[b]`/`[i]`/`[strike]`/`[spoiler]`, `[code]...[/code]` glued directly to following text/blocks, bare YouTube/Steam store/Workshop URLs for standalone embeds, flattened lists with `› ` prefixes inside `[list]`/`[olist]`, `[quote]`, native `[table][tr][th]/[td]`, `[hr][/hr]`, `[noparse][[/noparse]` escaping, and warnings for unsupported color/center/callout/task/math/footnote/start-number constructs). Show conversion problems only when exporting and ask before applying lossy fallbacks without silently omitting content.

## Visual Blocks

Use the existing Tiptap document model. Support headings, text styles, lists, tasks, tables, quotes, code (including variable-length CommonMark ` ```` ` / `~~~~` fences when inner backtick runs exist), links, images, spoilers, centered blocks, colors and Obsidian callouts. Provide block drag handles, an insertion menu triggered by /, and actions to change block type, duplicate and delete. Keep ordinary Markdown on disk. Pasting valid Markdown into Visual mode (`parsePastedMarkdown` and `MarkdownPaste` in `src/markdown.js`) parses and inserts formatted nodes/marks (except inside code blocks/inline code, or when clipboard already holds rich HTML, plain text, bare URLs, or unsupported/unsafe HTML).

Callouts use > [!type] Title, optional + or - for folding, and nested Markdown blocks. Preserve unknown callout identifiers with neutral styling. Opening or switching modes without editing preserves source. Unknown or unsafe markup remains source-editable rather than silently discarded.

## Hybrid Editing

Offer Visual, Hybrid and Source. Visual remains the default. In Hybrid, only the active top-level enclosing block mounts a CodeMirror 6 editor with Obsidian-style line/item-level Live Preview, while surrounding blocks stay rendered and untouched sibling DOM nodes are preserved incrementally across non-splitting edits. Inside the active block, cursor-touched lines reveal distinct raw syntax markers while inactive sibling lines render headings, bullets, interactive task checkboxes, callout badges/colors, dividers and inline formatting live without altering raw source on disk. Clicking a preview maps onto the nearest raw cursor offset; vertical arrow navigation crosses soft-wrapped visual lines, multi-line widget lines and adjacent block boundaries while preserving column; Backspace/Delete at block edges removes adjacent top-level blank-line separators; preview and Live Preview task checkboxes toggle directly; links expose hover popovers and `Ctrl+Click` opening; Enter continues or clears lists, tasks, quotes and callouts while Tab/Shift+Tab indent list lines; `/` triggers a live-filtering slash menu with aliases and Image insertion on any empty or command line; Block Actions provide a `Turn Into` submenu; multi-selected blocks support `Wrap In` and `Delete`/`Backspace` removal; and non-empty text selections open the shared floating bubble bar. Both Visual and Hybrid center gutter drag handles and `+` controls vertically on short horizontal rules (`---`) while locking hover across the approach band. Incomplete active Markdown remains editable and autosaved; Source remains the full-document fallback, including frontmatter.

## Interface And Preferences

Keep light/dark appearance, standard file shortcuts, middle-mouse-button tab closing (`auxclick` release to allow drag-away cancellation), source-conflict Diff View and non-intersecting auto-sync, selection-aware formatting controls, and cleaned-up native right-click context menus (`src/context-menu.js` suppresses menus on non-text UI chrome while `ContextMenuRequested` in `src-tauri/src/main.rs` strips WebView2 browser clutter to keep Cut/Copy/Paste, Undo/Redo, Select All, and spellcheck in editable regions plus `Copy` on read-only selections alongside custom Folder Browser and table-edge menus). Retain the split Color button, last-applied color and Hex/RGB/HSL preferences across launches, plus the global iconized header `NexusMods.svg | Steam.svg` BBCode dialect switch, the global document-bar `Width [Page | Full]` segmented toggle (`800px` centered column across Visual, Hybrid and Source by default, or full editor width), the global Document Outline mode (`Off` / `Float` / `Dock`, persisted as `outlineMode` in `session.json`), and window size/position persistence via `tauri-plugin-window-state` (`window-state.json`) with startup off-screen and taskbar rescue. Property settings are optional and shown only for explicit legacy document metadata. No automatic system file associations.

## Validation

Check source-only saving and migration, explicit export replacement and warnings, Nexus and Steam BBCode export/import parity (including paragraph/heading blank lines, glued `[list][*]...` openings with `\n` after `[/list]`, `\n` around `[hr]`, `[quote]`/callout and `[code]` blocks, and Steam tag/embed/table/glue rules), table/task/callout round trips, block actions and undo, Hybrid source fidelity and navigation, malformed source preservation, color selection/persistence and native startup/restart. Leave live Nexus/Steam publishing and Windows association changes to the user.

## Hybrid Spacing And Icons

Each actual top-level blank line is an independent editable block. A content block retains its terminating newline on disk without exposing that terminator as an extra editable row. Internal list, callout and code spacing stays inside the enclosing block. Gutter controls occupy no document height. Moving or deleting separators can intentionally change Markdown grouping; do not invent blank lines during moves.

Use locally bundled Google Material Symbols Rounded SVGs for file, formatting and block actions, alongside `NexusMods.svg` and `Steam.svg` for BBCode dialect controls and preview headings. Provide accessible names and hover/focus tooltips, including shortcuts where available. Retain text for modes, dropdowns, menus and confirmations. Include the Apache 2.0 license in portable releases.

Block-type and block-action entries in Turn Into, Block Actions, Insert and slash menus show matching icons alongside their text, including distinct Heading 1, 2 and 3 symbols.

## Editing Ergonomics, Preview And Search

Visual block gutter controls sit outside text padding without overlapping content, and Turn Into separates block conversions from block actions. Visual mode exposes contextual row/column table controls inside tables and inline callout type/folding selectors. Hybrid and Source support active formatting state, toggleable inline markers, formatting clear and formatting shortcuts. A toggleable live BBCode split preview pane, cross-mode Find and Replace, word/character counts, smart `.txt` format detection (opening Markdown/plain `.txt` directly in-place while routing BBCode-tagged `.txt` and `.bbcode` files through one-time Import), a resizable left Folder Browser sidebar, and window file/folder drag-and-drop complete the desktop workflow.

## Folder Browser

Provide a resizable, collapsible left-side `Files` sidebar (`Ctrl+Shift+E`, open by default on launch, with header toggle, close button and width/state persistence across launches). Zero-setup navigation auto-follows the active document's folder unless a workspace root was explicitly opened, climbed to via clickable breadcrumbs/parent navigation, or chosen from Persistent Pinned/Recent folders (keeping locked monorepo roots fixed on outside tab switches while offering one-click `Reveal Active File`). Filter listings to readable formats (`.md`, `.markdown`, `.mdbbcode`, `.txt`, plus `.bbcode` with an `Import` badge) across regular files, hard links, directory junctions, and symlinks (including extensionless symlinks pointing to readable targets, with cycle-guarded traversal and link-preserving saves) and hide dot/dependency/asset/empty directories by default (including asset-only `Dist`/`Build` folders while showing `Dist`/`Build` folders that hold readable files or symlinks) with an `All` toggle (`Show All Folders`) plus recursive substring search. Automatically refresh the visible tree and expanded folders (preserving scroll position and real path casing, and deferring while collapsed or during inline actions) whenever Markdown BBCode becomes the active window. Include Light Explorer actions: inline `+ New File` (defaulting `.md`, refusing overwrites), inline `Rename` (`F2`/context menu, synchronizing open tabs), context menu (`Open`, `Import As BBCode` for `.txt`, `New File`, `Open As Root`, `Pin`/`Unpin`, `Rename`, `Reveal In Explorer`, `Copy Path`), and folder drag-and-drop.

## Notion-Style Interactions, Tables And Resizable Synced Preview

The BBCode preview pane supports a draggable resize splitter (vertical on desktop, horizontal when stacked) and bidirectional block-anchored scroll sync. The toolbar Table button opens an `8 × 8` size grid with header-row selection; the contextual table bar reflects `Header Row` state, and Visual tables expose right/bottom `+` hover rails, row/column drag handles (click for menu, drag to reorder while keeping row `0` headers normalized) and edge-only right-click menus while keeping cell interiors native. Visual and Hybrid block handles use pointer-event drag-and-drop with vertical hit-testing locked onto hovered controls; Visual lists and containers support per-item handles following nesting, drag-to-nest list items and Callouts/containers, and Shift/Ctrl+Click plus left-gutter marquee multi-block selection with a floating batch bar. Visual editing adds an active-line `/` placeholder, expanded slash/Turn Into entries and aliases (including Divider, Toggle, Spoiler, Center and Image), smart URL paste on selection across all modes, a link hover/caret popover (with validated native external URL opening), an expanded selection bubble bar (`Turn Into`, swatches, `Choose Color…`, `Clear Color`), a code block language/copy bar, an image hover pill with a two-field URL/alt dialog, cross-mode shortcuts (`Ctrl+K`, `Ctrl+Shift+X`, `Ctrl+E`, `Ctrl+Alt+0`–`6`, `Alt+Up`/`Down`), and a right-side three-state Document Outline (`Off` / `Float` / `Dock`) with scroll-tracked headings across Visual, Hybrid and Source.

## Markdown Lint

Linting is opt-in and must never cost startup or shutdown time. markdownlint (`markdownlint/sync`) is imported only by `src/lint/lint-worker.js`, a module Web Worker that `src/main.js` creates lazily on the first lint after linting is enabled; never import markdownlint from the main bundle. `src/lint/lint-controller.js` debounces edits (400 ms, 2 s max wait), keeps one request in flight, drops results whose text has changed and lints only the active document; documents over 300 KB lint only on demand. `src/lint/lint-config.js` owns the app rule profile (MD013/MD028/MD041 off, `span`/`center`/`details`/`summary`/`br`/`sup`/`sub`/`u`/`kbd`/`mark` allowed for MD033, sibling-only MD024, no frontmatter title for MD025); every problem is a warning unless its rule is configured as `error`. `src/lint/lint-panel.js` owns the docked pane's `Outline | Lint` tabs, grouped problem list, footer count and click-to-jump (Source selects the exact range, Hybrid activates the containing block at the offset, Visual selects the nearest top-level block). The worker build aliases `decode-named-character-reference` to its non-DOM entry because workers have no `document`. Lint settings persist as `lint` (`enabled`, `preset`, `rules`, `debounceMs` 150–2000 default 400, `largeFileKB` 50–5000 default 300) and the selected tab as `rightPanelTab` in `session.json`; older `{ enabled }` sessions still load.

The Settings dialog (header gear, `Ctrl+,` by comma character or `VK_OEM_COMMA`) is a modal in the Diff View style with a left `General | Linting` nav; it is built by a lazily imported chunk and every change saves at once. General mirrors the header's BBCode dialect, `Width` and Outline controls through the same setters, so both stay in sync. Linting holds the master toggle, `Lint Delay` and `Large File Threshold`, a `Preset` select (`Markdown BBCode Default` = the app profile, `markdownlint Default`, `Relaxed` = markdownlint's lazy-loaded `style/relaxed.json`) and a rule browser generated from markdownlint's config schema: search by id, alias or description, a category filter derived from rule tags (Headings, Lists, Whitespace, Code, Links & Images, Style), `Only Modified`, and per rule an enabled checkbox, `Warning | Error` severity, typed option editors (checkbox, number with minimum, select, text, comma-separated lists), `Reset` and a documentation link. Edits are stored as per-rule overrides under `lint.rules` only when they differ from the preset (`"error"` or `{ ...options, severity: "error" }` for Error); the effective config is the preset with overrides appended so they beat preset aliases and tags. When the active document has a `.markdownlint.jsonc` or `.markdownlint.json` in its folder or an ancestor (up to a locked Folder Browser root, otherwise the drive root; relative `extends` supported), that file replaces the app config for the document and the Linting page shows `Using <path> (read-only)` with the rule browser disabled; YAML, rc, `.cjs` and `.mjs` configs are detected but not used, with a notice.

Inline markers (`Show Inline Markers`, `lint.markers`, default on) appear only while linting is on and a result matches the current text. Hybrid rendered blocks with problems get a 2 px amber (warning) or red (error) left-edge mark drawn as an absolute pseudo-element in the gutter, so source spans and height never change; the active block instead gets wavy underlines whose hover tooltip shows the rule code, description, detail and a `Fix` button. Visual marks the containing top-level block the same way via a ProseMirror node decoration (same nearest-block mapping as the Lint tab's jump). Source stays a plain textarea without underlines. The floating outline rail gets small proportional amber/red problem ticks along its left edge without affecting heading ticks or the popover. Fixable problems show `Fix` (rows and the Hybrid tooltip) and the Lint toolbar shows `Fix All`; Source fixes are native undoable textarea edits, Hybrid fixes go through the hybrid source update path, and Visual fixes first ask (`Fixing in Visual mode resets undo history`, with `Fix Anyway`, `Switch to Source` and `Cancel`). Fixes always go through capture and autosave.

## Packaging And Updates

`npm run portable` compiles `markdown-bbcode.exe` and deploys directly to `D:\Apps\Markdown BBCode\Markdown BBCode.exe`, keeping `portable-data` intact and triggering graceful close via `--graceful-close` (single-instance IPC) with a `WM_CLOSE` fallback (waiting up to `10s` and aborting safely if blocked by a save/conflict dialog) before swapping and relaunching an already-open instance in that folder. `npm run build:installer` produces a per-user signed NSIS installer (`currentUser`, storing data under `%APPDATA%\Markdown BBCode` with one-time legacy migration from `%APPDATA%\BBCode Editor`). Both modes check GitHub Releases asynchronously after startup or on demand from the footer version button (`vX.Y.Z`) and provide a one-click header `Update` pill that flushes open documents (blocking if any unresolved conflict/save error exists) before delegating to `tauri-plugin-updater` (installed) or verifying SHA-256 + Ed25519 minisign signatures and extracting non-user files safely (portable). Official GitHub Releases run only via `.github/workflows/release.yml` on manual dispatch or `release/v*` tag push.
